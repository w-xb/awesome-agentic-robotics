# Agentic Robotics Taxonomy

This document explains the organizing view behind **Awesome Agentic Robotics**. It is intended as a research map rather than a claim that every embodied system cleanly separates into independent modules.

## The Agent–Harness–VLA Loop

```text
Goal / Human Intent
        ↓
Agent / Planner
(reasoning · decomposition · task state)
        ↓
Harness / Runtime
(memory · tools · routing · verification · recovery · safety)
        ↓
VLA / Policy
(grounded perception-to-action execution)
        ↓
Robot + Physical World
        │
        └── observations · outcomes · failures ──↺

Persistent validated updates across episodes → Self-Evolution
```

The stack is useful because it separates three questions that are often conflated in embodied-agent discussions:

- **Agent:** What should the system do next, and why?
- **Harness:** How are components coordinated, checked, routed, retried, recovered, and constrained during execution?
- **VLA / policy:** How is grounded multimodal context converted into executable physical actions?

The physical world closes the loop by supplying consequences. Memory and world models preserve or predict state across time, while verification and recovery determine whether execution should continue, be repaired, or be handed back to a human or higher-level planner.

## Layers

| Layer | Primary responsibility | Typical research questions | Typical persistent evolution target |
| --- | --- | --- | --- |
| **Agent / Planner** | Task decomposition, deliberation, subgoal selection, replanning. | How should goals be decomposed? When should the system replan? Which skill or policy should be invoked? | Planning strategy, prompts, programs, subgoal policies. |
| **Harness / Runtime** | Orchestration around the policy. | How should memory, tools, verifiers, recovery logic, routing, and safety guards interact at runtime? | Tool schemas, critics, recovery playbooks, contracts, routing rules, runtime guards. |
| **Memory / Context** | Persistent or retrieved state beyond the current observation. | What should be remembered? How should memories be consolidated, retrieved, updated, or forgotten? | Episodic memory, semantic memory, task state, retrieval policy. |
| **World Model** | Prediction of future observations, dynamics, outcomes, or action consequences. | Which futures matter for control? How should imagined rollouts be evaluated and grounded? | Predictive dynamics, latent state, candidate-evaluation model. |
| **VLA / Policy** | Grounded perception-to-action execution. | How should multimodal context map to continuous or discrete robot actions? | Policy weights, adapters, action representations, online data. |
| **Skills / Tools** | Reusable executable capabilities exposed to the agent. | How should skills be discovered, represented, composed, validated, and selected? | Skill libraries, code tools, ROS/API interfaces, physical-tool abstractions. |
| **Verifier / Safety Layer** | Evaluation of success, correctness, constraint satisfaction, and risk. | Did execution succeed? Is the next action safe? Is the trajectory consistent with a task contract? | Verifiers, temporal specifications, guards, success criteria. |
| **Physical World / Evaluation** | Consequences and evidence generated by interaction. | Which benchmarks expose long-horizon, safety, recovery, or generalization failures? | Datasets, benchmarks, evaluation protocols, fleet experience. |

## What Counts as Self-Evolution?

For this repository, **self-evolution requires a validated change that persists and affects future episodes**. The persistence criterion is important because many agentic behaviors adapt within a single task without actually changing the system for later tasks.

We therefore distinguish:

- **Transient adaptation:** replanning, retrying, chain-of-thought, temporary context changes, or test-time search that disappears after the episode.
- **Persistent evolution:** accepted changes to skills, memory, verifiers, objectives, policies, data, tools, or the runtime harness that are reused later.

The main evolution targets used in the repository are:

- `harness/runtime`
- `skill/library`
- `contract/verifier`
- `policy/data`
- `objective/reward`
- `memory/context`

## Canonical Placement Rule

Many papers span several layers. To keep the list useful, each paper receives **one canonical placement based on its primary agentic contribution**, not every mechanism it contains.

Examples:

- A system that uses memory but mainly contributes a failure-recovery supervisor belongs under **Failure Detection and Recovery**.
- A VLA that happens to use a world model but primarily contributes long-horizon policy execution belongs under **Agentic VLA** or **Long-Horizon Manipulation**.
- A method whose central contribution is persistent skill consolidation belongs under **Self-Evolving Embodied Agents**, even if planning and verification are also involved.

Secondary capabilities should be described in the entry instead of duplicating the paper across sections.

## Research View

This taxonomy suggests that progress in agentic robotics is not only a matter of scaling a monolithic VLA. Reliable long-horizon autonomy increasingly depends on how reasoning, memory, world models, reusable skills, verification, recovery, safety, and low-level control are coordinated as one closed-loop system.

A particularly important open direction is **cross-layer co-evolution**: instead of improving the agent, harness, memory, verifier, or policy independently, future systems may need mechanisms that evolve these components jointly while preserving compatibility, safety, and stable physical behavior.
